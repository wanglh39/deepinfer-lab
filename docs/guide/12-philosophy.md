# 12 设计哲学总结：十条原则

把前面十一章的解读与 miniflow 开发中的真实教训合在一起，哪些原则值得带进你自己的系统设计？本章是全书的收束：十条原则按「来源」分成两半——前五条从 DeepInfer 的架构读出，后五条从 miniflow 的踩坑中学到，每条附原始出处。

十条原则不是并列的清单——它们有内在的结构：前三条讲**系统怎么切**（算子/负载/状态），第四五条讲**边界怎么定**（确定性/编译运行），后五条是**代码怎么写**的正确性纪律（顺序/原子/增量/显式/可测试）。可以当成一份「review checklist」用：接手任何新系统，按这十条各问一句，半小时内能摸清它的设计质量和风险热点。

每条原则的格式：**一句话的规则 + 为什么（机理）+ 反例（违反的样子）+ 你的行动**。所有出处都指向具体章节——原则没有凭空的，全部长在具体案例上。

## 上半：从 DeepInfer 读出的五条

## 原则一：算子决定上限，引擎决定下限

乘法发生在算子里——调度再好也只是把形状合适的输入递给算子（[04 内核层](04-kernels.md)）。一个占 60% 时间的算子慢 20%，全系统慢 12%，任何调度技巧都救不回来。反过来说，算子不好引擎也烂不到哪去——所以下限由引擎保证、上限由算子决定。

**机理**：算术强度的物理约束（第 01 章）——2 FLOPs/byte 的负载里，调度优化的是「搬运的摊销」，算子优化的是「搬运的效率」，前者有上限（摊到极限就是 1 倍权重读取）后者没有（flash 系列证明搬运次数还能压）。

**反例**：团队在调度器上迭代半年（chunk 预算、优先级、抢占策略全套），MFU 始终 40%——瓶颈在通用注意力 kernel 上，调度已经把它能摊的都摊完了。

**行动**：接手系统第一件事，profile 算子占比（哪个 kernel 吃掉 60% 时间）——**先看算子形状再谈架构**，是性能工作的入场券。

## 原则二：负载特性驱动架构，而不是反过来

prefill 计算受限、decode 访存受限，于是 P/D 物理分离；MoE 的通信随 EP 规模线性增长，于是 DeepEP 装两副牙齿；decode 是高频小消息，于是有低延迟内核。DeepGEMM 的两种模式甚至是「分离部署」在算子层的投影（[03](03-architecture.md)/[04](04-kernels.md)）。

**机理**：同一硬件对不同负载的最优配置相反（第 03 章 1.3 节的对照表）——负载的物理属性（算术强度、消息尺寸、频率）决定资源的最优分配，架构只是分配的表现形式。

**反例**：「我们先搭一个微服务框架（注册中心、网关、消息队列全套），再往里塞业务」——结果每条消息的路由开销比业务处理还贵。**先画框图再找理由的架构，组件之间总会对不上**。

**行动**：新系统设计时，先写一页「负载画像」（QPS、请求大小分布、读写比、延迟敏感度），让框图从画像里**长出来**而不是画出来。

## 原则三：最贵的是状态，最难的是生命周期

KV Cache 是全系统最大的状态，DeepInfer 未开源的组件恰好是它的管理器（[06 KV Cache](06-kvcache.md)）。引用计数、TTL、按层进度——系统复杂度的真正来源是**状态的归属与回收**，不是计算本身。

**机理**：计算是无状态的流（算完就释放），状态是滞留的物（要管理归属、回收时机、故障恢复）——第 03 章的故障剧本规律「破坏力 ∝ 状态量」是这个贵感的量化。

**反例**：回忆你维护过的任何难缠系统——连接池的泄漏排查、缓存的一致性 case、任务的重复执行——**多半不是算法难，是「谁拥有这个状态、什么时候释放」没说清**。

**行动**：设计评审时专门有一页「状态清单」：每个长生命周期对象，写清归属者、生命周期、故障时谁恢复。**说不清的状态就是未来的事故**。

## 原则四：确定性是正确性问题，不是 nice-to-have

batch-invariant + seq_seed 让「同输入同输出」成为可测试的硬契约（[09 采样](09-sampling.md)）。不可复现的系统无法回归、无法 A/B 对比、无法分片审计——它没有质量体系，只有运气。把确定性放在「尽力优化」的清单里，等于承认自己的测试全是噪声。

**机理**：浮点归约顺序、RNG 流位置这些「无害的漂移」经长序列放大成必然分岔（第 09 章 2.1 节的放大链）——**非确定性不是小概率事件，是每一步都在发生的、被序列长度放大的熵增**。

**反例**：「我们的服务大部分时候是确定的」——这句话等于说「我们的测试大部分时候是对的」。回归测试在非确定系统上只有两种状态：绿（没测到）和随机红（没人信）。

**行动**：把「同 (input, seed) → 同 output」写进系统的第一条契约测试——写不出来，就先修确定性再谈别的。

## 原则五：编译与运行解耦，缓存编译产物

语法自动机异步编译在专用机器（[10 结构化输出](10-structured.md)）；成本模型离线拟合、在线反解（[07 调度器](07-scheduler.md)）；TileLang 编译期生成 GPU 核（[04](04-kernels.md)）。共通模式：**把纯 CPU 逻辑从 GPU 的毫秒级关键路径上摘下来**，产物可缓存、机器可分离、故障可隔离。

**机理**：编译（重、确定性、可缓存）和运行（轻、动态、每次执行）的代价曲线完全不同——混在一起时，运行路径被迫承受编译的延迟方差；分开后编译的产物变成「数据」，享受缓存的全部经济学（第 02 章 Zipf 头部）。

**反例**：正则表达式在请求处理器里现场 `re.compile`——每条请求多付 100 μs，而 99% 的 pattern 是重复的；数据库每次查询都做完整执行计划（无 prepared statement 缓存）。

**行动**：审视运行路径上「每次现算、算完就扔」的逻辑——schema 解析、配置展开、布局计算——**任何确定性重计算都是编译的候选人**。

## 下半：从 miniflow 踩坑学到的五条

## 原则六：顺序是正确性问题，不只是性能偏好

miniflow 调度器的第三重死锁：先接纳 prefill 再组 decode，导致「接纳-抢占」震荡，**每步零进展**（[07 调度器](07-scheduler.md)/[lab/04](../lab/04-scheduler.md)）。修复不是加锁不是加检查，只是调整顺序（decode 优先）。

**机理**：两个操作共享一份资源时，顺序决定「谁看到什么状态」——第 07 章把它列为分布式系统的普适定律。**顺序是隐式的不变量承载者**：代码的书写顺序悄悄编码了「先保谁、后查谁」的语义。

**反例**：先写文件再更新索引（崩溃在中间 = 文件和索引不一致）；先发消息再落库（消息消费方读到的状态比库新）；先加锁 A 再加锁 B，而另一个线程反过来——教科书死锁。

**行动**：code review 时对任何「先 A 后 B」问一句「反过来会怎样」——答不上来就说明顺序承载了没写下来的不变量，**写下来（注释或断言）**。

## 原则七：检查与分配必须原子，否则看到的是幻影

第二重死锁：同批 N 条序列的容量检查共享同一瞬间的空闲块数，每条都「看到」同一份富余，物理分配时爆炸（[lab/04](../lab/04-scheduler.md)）。

**机理**：「先检查后使用」的窗口期里，状态可能被改（别的循环、别的线程、甚至本循环的前一步）——**检查时的世界和使用时的世界不是同一个世界**。单线程不豁免：循环内前一次迭代的副作用同样污染下一次检查。

**反例**：余额检查后扣款（并发下双花）；库存查询后下单（超卖）；TOCTOU（time-of-check to time-of-use）是安全领域的经典漏洞类——**整整一类漏洞都是这个窗口**。

**行动**：任何资源分配代码，检查和落袋之间不允许任何其他操作（包括日志！）——或者用「检查即预留」的写法把窗口消灭在语法层。

## 原则八：增量思维——一切进度按层、按块推进

KV 的已算进度按层记账（`computed[seq][layer]`），它是断点续算、推测解码回滚、chunked prefill 三个特性的共同地基（[06](06-kvcache.md)）。把长任务拆成**可恢复的最小推进单位**，任何中断的代价才有上界——SWA 的 bounded replay 把「回滚代价」从序列长度锁死在窗口大小，是同一思想在模型结构层的一次预埋。

**机理**：中断代价 = 已推进但未确认的量。推进单位越小（层/块/chunk），「已推进未确认」的上界越小——故障、抢占、回滚的成本全部被单位粒度封顶。**粒度是风险的分母**。

**反例**：一个 30 分钟的批处理任务没有 checkpoint——失败一次重来 30 分钟；一个事务包住全部 10 步操作——任何一步失败全部回滚（长时间持锁 + 大回滚成本）。

**行动**：长任务设计时先定「最小可恢复单元」（一层/一块/一页），**中断代价的上界就是这个单元的大小**——它是你能接受的最小损失粒度。

## 原则九：显式优于隐式——编号、契约、状态都要传递

三个真实 bug 同根源：NFA 初始状态硬编码 0，而构造器从 1 起编号（[10](10-structured.md)）；spec 的 KV 回滚量靠分支内各自推导，没有统一显式公式（[08](08-speculative.md)）；`num_computed` 与 `kv.computed` 两个进度镜像靠约定对齐。

**机理**：隐式约定（编号从几开始、两个变量谁对齐谁）**存在于写代码那一刻的脑子里，之后只存在于考古现场**——第三个接手的人只看到两段「都对」的代码和一条看不见的连线。

**反例**：魔术数字（`if status == 3`——3 是什么？）；默认参数承担协议（「不传就是上次的模式」）；两处必须同步修改的代码没有共同出处（改一处漏一处）。

**行动**：所有跨模块的约定显式化为**传递的参数、断言的契约、或单一出处**——「约定俗成」在代码里是贬义词。**spec bug 正是被增量契约的 `assert n > 0` 当场抓住的**——断言就是显式化的约定在值勤。

## 原则十：可测试性是设计的输入，不是事后补丁

「spec 输出 == greedy」这条契约决定了教学版选 argmax 验证而非残差采样（[08](08-speculative.md)）；gradcheck 的数值梯度对照抓住了 train.py 四个反向传播 bug 中的三个（[lab/02](../lab/02-model.md)）。

**机理**：可测试的设计 = 行为有明确契约（可断言）+ 副作用可隔离（可 mock）+ 状态可恢复（可重放）——**这三个属性同时是「好设计」的定义**。测试写不出来 = 契约没想清 = 设计没做完。

**反例**：「功能先上，测试下个迭代补」——下个迭代永远在来路上；补测试时发现根本没法测（全局状态、隐式依赖、时钟耦合），被迫先重构——**测试债的利息是复利**。

**行动**：写实现之前先写「怎么证明它是对的」——测试用例列表就是设计的验收标准。**写不出测试的设计，多半是你还没想清**。

## 十条之外：三条没进榜的候选

诚实起见，列三条落选的（它们好但不够普适/或已包含在其他条里）：

**「闲时套利」**（第 01/08 章）：闲置算力换产出（组批、spec）——很好但它是推理领域的特定经济学，迁移面窄（已融入原则一、二的机理里）；

**「乐观启动 + 惰性接管」**（第 10 章）：无约束先跑、编译好了再接管——本质是「小赌注换确定收益」的期望值思维，可归入原则五的「编译运行解耦」的运行策略；

**「质量投资密度 ∝ 故障半径」**（第 04 章 4.5 节）：爆炸半径大的组件测试矩阵大——它是原则十的定量版，合并不单列。

如果你觉得有该进没进的——恭喜，说明你已经带着自己的经验读完全书了。**清单的正确用法是触发你自己的第十一条**，不是当圣经背。

## 收尾：从读懂到写出

```text
DeepInfer（生产）──解读──> 设计原理 ──实现──> miniflow（教学）
        ↑                                          │
        └──────────── 踩坑实录反哺理解 ←────────────┘
```

这个闭环是本书的教学法核心：解读给你**原理的形状**，实现给你**原理的重量**（每个「哦原来如此」都要在代码里扛过边界条件才算数），踩坑给你**原理的边界**（哪里想当然就翻车）。三条路走完，知识才是你的。

miniflow 的 17 个测试钉死的每条契约，都是对某一章原理的**可执行复述**。如果你准备深入某一块，建议路径：读对应的 guide 章节 → 读对应 lab 章节的实现与踩坑 → 动手改掉一个设计选择，看哪些测试变红——**红掉的测试就是你理解边界的坐标**。

几个具体的「改掉一个设计选择」的入口（难度递增）：

- **初级**：改 `CacheConfig.block_size`（4 → 8），跑全测试——哪些行为变了（尾浪费、命中粒度）？哪些测试红了？为什么红（它们在守护什么契约）？
- **中级**：把调度器的抢占策略从「最晚到达」改成「最大 KV 占用」——重跑 demo_scheduler 的三幕，观察公平性和吞吐的曲线怎么动；lab/04 的三重死锁在什么流量画像下会复活？
- **高级**：给 spec 加「draft 树」（一次验证多条候选路径——Medusa 式）——KV 回滚的不变量（`kv_keep` 公式）怎么推广到树形接受？第 08 章的分布不变性数学还成立吗（树形的残差采样是 open research）？

最后一个建议是关于**读源码**的：带着本书的地图去读 DeepInfer 或 vLLM 的真实代码。你会看到比 miniflow 复杂 100 倍的工程细节（错误处理、配置矩阵、平台兼容），但骨架和 miniflow 同构——**你已经有了骨架的地图，剩下的细节迷路不了你**。反过来，读完真代码再回来对 miniflow，会对「教学取舍」的精确性有新的敬意：删掉了什么、保留了什么、为什么。
