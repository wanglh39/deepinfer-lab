# 12 设计哲学总结：十条原则

把前面十一章的解读与 miniflow 开发中的真实教训合在一起，哪些原则值得带进你自己的系统设计？本章是全书的收束：十条原则按「来源」分成两半——前五条从 DeepInfer 的架构读出，后五条从 miniflow 的踩坑中学到，每条附原始出处。

## 原则一：算子决定上限，引擎决定下限

乘法发生在算子里——调度再好也只是把形状合适的输入递给算子（[04 内核层](04-kernels.md)）。一个占 60% 时间的算子慢 20%，全系统慢 12%，任何调度技巧都救不回来。反过来说，算子不好引擎也烂不到哪去——所以下限由引擎保证、上限由算子决定。设计系统时先问「热点路径的算子形状是什么」，再谈架构。

## 原则二：负载特性驱动架构，而不是反过来

prefill 计算受限、decode 访存受限，于是 P/D 物理分离；MoE 的通信随 EP 规模线性增长，于是 DeepEP 装两副牙齿；decode 是高频小消息，于是有低延迟内核。DeepGEMM 的两种模式甚至是「分离部署」在算子层的投影（[03](03-architecture.md)/[04](04-kernels.md)）。**先量化负载，再画框图**——先画框图再找理由的架构，组件之间总会对不上。

## 原则三：最贵的是状态，最难的是生命周期

KV Cache 是全系统最大的状态，DeepInfer 未开源的组件恰好是它的管理器（[06 KV Cache](06-kvcache.md)）。引用计数、TTL、按层进度——系统复杂度的真正来源是**状态的归属与回收**，不是计算本身。回顾你维护过的任何难缠的系统，多半不是算法难，是「谁拥有这个状态、什么时候释放」没说清。

## 原则四：确定性是正确性问题，不是 nice-to-have

batch-invariant + seq_seed 让「同输入同输出」成为可测试的硬契约（[09 采样](09-sampling.md)）。不可复现的系统无法回归、无法 A/B 对比、无法分片审计——它没有质量体系，只有运气。把确定性放在「尽力优化」的清单里，等于承认自己的测试全是噪声。

## 原则五：编译与运行解耦，缓存编译产物

语法自动机异步编译在专用机器（[10 结构化输出](10-structured.md)）；成本模型离线拟合、在线反解（[07 调度器](07-scheduler.md)）；TileLang 编译期生成 GPU 核（[04](04-kernels.md)）。共通模式：**把纯 CPU 逻辑从 GPU 的毫秒级关键路径上摘下来**，产物可缓存、机器可分离、故障可隔离。任何「每次都要现算、算完就扔」的逻辑都值得问一遍能不能编译。

---

## 原则六：顺序是正确性问题，不只是性能偏好

miniflow 调度器的第三重死锁：先接纳 prefill 再组 decode，导致「接纳-抢占」震荡，**每步零进展**（[07 调度器](07-scheduler.md)/[lab/04](../lab/04-scheduler.md)）。修复不是加锁不是加检查，只是调整顺序（decode 优先）。当你发现某个执行顺序「只是写代码时的习惯」，警惕——它可能是某条不变量的隐式承载者，换掉它就换掉了正确性。

## 原则七：检查与分配必须原子，否则看到的是幻影

第二重死锁：同批 N 条序列的容量检查共享同一瞬间的空闲块数，每条都「看到」同一份富余，物理分配时爆炸（[lab/04](../lab/04-scheduler.md)）。**任何「先检查后使用」的窗口期都是竞态**——即使单线程，窗口期里被另一个循环改掉的状态同样构成竞态。让检查通过的一瞬间就完成资源落袋，不留窗口。

## 原则八：增量思维——一切进度按层、按块推进

KV 的已算进度按层记账（`computed[seq][layer]`），它是断点续算、推测解码回滚、chunked prefill 三个特性的共同地基（[06](06-kvcache.md)）。把长任务拆成**可恢复的最小推进单位**，任何中断的代价才有上界——SWA 的 bounded replay 把「回滚代价」从序列长度锁死在窗口大小，是同一思想在模型结构层的一次预埋。

## 原则九：显式优于隐式——编号、契约、状态都要传递

三个真实 bug 同根源：NFA 初始状态硬编码 0，而构造器从 1 起编号（[10](10-structured.md)）；spec 的 KV 回滚量靠分支内各自推导，没有统一显式公式（[08](08-speculative.md)）；`num_computed` 与 `kv.computed` 两个进度镜像靠约定对齐。**隐式约定在第三个人接手时变成地雷**——显式传参、显式断言：spec bug 正是被增量契约的 `assert n > 0` 当场抓住的。

## 原则十：可测试性是设计的输入，不是事后补丁

「spec 输出 == greedy」这条契约决定了教学版选 argmax 验证而非残差采样（[08](08-speculative.md)）；gradcheck 的数值梯度对照抓住了 train.py 四个反向传播 bug 中的三个（[lab/02](../lab/02-model.md)）。**先写下「怎么证明它是对的」，再写实现**——测试不是交付前的质量门，是设计过程本身：写不出测试的设计，多半是你还没想清。

DeepInfer（生产）──解读──> 设计原理 ──实现──> miniflow（教学）
        ↑                                          │
